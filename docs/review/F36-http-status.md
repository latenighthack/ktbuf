# F36 — exact unary HTTP status metadata

Reproduction: the real CIO/generated-service/HTTP-client fixture sends opaque error bodies for every RPC status. Before the fix, shared HTTP statuses erased permanent operation codes (`ALREADY_EXISTS` became retryable `ABORTED`; `FAILED_PRECONDITION` and `OUT_OF_RANGE` became `INVALID_ARGUMENT`; `DATA_LOSS` became retryable `UNKNOWN`). A conflicting HTTP 401 / numeric OK header was also unchecked. Two of three initial HTTP regressions failed; the legacy fallback regression passed (`/tmp/runtime-ktbuf-status-red.log`).

Unary service responses now emit numeric `grpc-status`, including successful and bounded-encoding error responses. The server exposes this header to browser clients when an embedding host enables CORS. JVM, Android, JS, and Apple implementations of both `HttpRpcClient` and `PlatformHttpClient` read it. Exact metadata must name a known numeric code and match that code's canonical HTTP status; malformed, conflicting, or duplicated metadata is permanent `DATA_LOSS`. Success responses also validate metadata, so an error cannot masquerade as a decoded successful payload. Missing metadata keeps the original HTTP/body fallback unchanged. The original two-argument `Status.fromHTTPCode` function remains available; the new three-argument overload preserves its ABI.

The underlying retry policy is unchanged: UNKNOWN, CLIENT_TIMEOUT, DEADLINE_EXCEEDED, RESOURCE_EXHAUSTED, ABORTED, INTERNAL, and UNAVAILABLE are transient. Other statuses remain terminal. Actual HTTP tests cover every failure code with an opaque body using both JVM client APIs, conflicting/malformed/duplicate metadata, legacy endpoints without metadata, and a caller deadline which remains coroutine cancellation. Common tests repeat exact code and retry policy validation on all tested platforms.

Validation: server selected HTTP/stream transport tests 15; library JVM/Android debug/JS Node/macOS ARM64 90 per target; RPC JVM/Android debug 24 per target, JS Node 17, macOS ARM64 23. All pass with zero skips. iOS simulator ARM64 RPC compilation passes. Logs: `/tmp/runtime-ktbuf-status-final.log`, `/tmp/runtime-ktbuf-status-matrix.log`, `/tmp/runtime-ktbuf-status-apple.log`. The initial broad Apple run found a stale large-stream fixture passing a `ws://` constructor URL after HTTP base-address normalization; its fixture now uses the valid HTTP base and joins owned client shutdown, retaining the same real 1,142,787-byte Foundation stream assertion.

This paired commit is built in its own worktree from publisher revision 6123444. The integrating lockers runtime uses a separately published immutable dependency pin and tests the same status contract across a public seed and authenticated private peer; no generated binding was edited.
